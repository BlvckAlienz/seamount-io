### Step-by-Step Process to Commit and Push

#### 1. Stage Only Tracked Changes
Since you have modified and deleted files you want to commit, and untracked files (like `backend/.env.production`) you want to exclude, use the following command to stage only tracked files:

```bash
git add -u
```

- **What it does**: Stages all modified and deleted files that are already tracked by Git, ignoring untracked files.
- **Why**: This prevents accidentally adding sensitive untracked files to your commit.

#### 2. Verify What’s Staged
Double-check the staged changes to ensure only the intended files are included:

```bash
git status
```

- **Expected output**: You’ll see a list of staged files (e.g., modified files and deletions) under "Changes to be committed." Untracked files should remain under "Untracked files" and not be staged.
- **Next, check for sensitive data**: Run this command to scan staged changes for potential leaks:

```bash
git diff --cached | grep -i "key\|secret\|password"
```

- **If nothing appears**: You’re good to proceed.
- **If something appears**: Edit the offending files, remove sensitive data, and re-run `git add -u` followed by the check.

#### 3. Commit Your Changes
Create a commit with a clear, meaningful message:

```bash
git commit -m "Update backend and frontend, remove deprecated components"
```

- **Why a good message matters**: It helps you (and any future collaborators) understand the purpose of these changes later.
- **Optional tweak**: If your project has a convention (e.g., `[Backend] Update and refactor`), adjust the message accordingly.

#### 4. Push to GitHub
Push your commit to the remote repository on the `main` branch (adjust if your branch is different):

```bash
git push origin main
```

- **Authentication**: Since you’re using HTTPS with a Personal Access Token (PAT):
  - When prompted, enter your GitHub username.
  - For the password, paste your PAT (stored securely, right?).
- **Success**: You’ll see output confirming the push, like `To https://github.com/username/repo.git`.

#### 5. Verify on GitHub
Head to your GitHub repository in a browser:
- Check that the latest commit appears in the commit history.
- Browse the updated files to confirm the changes are reflected as expected.

### Quick Troubleshooting
- **Push fails with authentication error**: Double-check your PAT. If it’s expired or incorrect, generate a new one from GitHub Settings > Developer Settings > Personal Access Tokens.
- **Untracked files got staged**: If you accidentally used `git add .` earlier, reset staging with `git reset` and re-run `git add -u`.
- **Sensitive data detected**: Abort the commit with `git reset --soft HEAD^`, fix the files, and restart from step 1.
